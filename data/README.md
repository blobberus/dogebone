# Data

```
data/
├── raw/
│   ├── prices/      <- drop DOGE (and optionally BTC) daily price files here
│   └── tweets/      <- drop tweet exports here (one combined file or one file per account)
├── sample/          <- SYNTHETIC data generated by scripts/make_sample_data.py (pipeline testing only)
├── reference/       <- hand-curated reference data (key events timeline)
└── processed/       <- notebook outputs (scored tweets, metrics); git-ignored
```

The notebook uses `data/raw/` when it finds both price and tweet files, and otherwise falls back to
`data/sample/` with a loud warning. **Never present results computed on `data/sample/`.**

## Price files: `data/raw/prices/`

| Requirement | Detail |
|---|---|
| File name | Must contain `doge` (e.g. `doge_daily.csv`). An optional `btc*.csv` enables market-adjusted returns. |
| Format | CSV (comma or semicolon; delimiter is auto-detected) |
| Timestamp convention | If the file stamps a 00:00 UTC snapshot (CoinGecko `snapped_at`), set `price_is_start_of_day_snapshot=True` in the notebook config. |
| Frequency | Daily, **UTC** candles, 2021-01-01 to 2022-12-31. Add ~10 days of padding on both ends so 7-day forward returns exist at the edges. |
| Required columns | a date column and a close column |
| Optional columns | `open`, `high`, `low`, `volume` |

Accepted column names (case-insensitive). The loader maps any of these automatically:

| Canonical | Accepted aliases | Typical source |
|---|---|---|
| `date` | `date`, `timestamp`, `time`, `snapped_at`, `timeOpen`, `datetime` | Yahoo / CoinGecko / CoinMarketCap |
| `close` | `close`, `adj close`, `price`, `close_price`, `closing_price` | |

Investing.com style values (`"0.0891"`, `"1.2B"` volume, `"-3.1%"`) are cleaned automatically.

## Tweet files: `data/raw/tweets/`

| Requirement | Detail |
|---|---|
| Format | `.csv`, `.json` (list of objects), or `.jsonl` |
| Scope | DOGE-related posts from the accounts in [`config/accounts.csv`](../config/accounts.csv), 2021-01-01 to 2022-12-31 |
| Required fields | timestamp, text, account handle (*or* one file per account named `<handle>.csv`) |
| Timestamps | **Full timestamps with time of day** (UTC preferred). Date-only data still works but loses the intraday alignment logic. Naive timestamps are treated as UTC. |

Accepted column names (case-insensitive, nested JSON is flattened with `.`):

| Canonical | Accepted aliases |
|---|---|
| `created_at` | `created_at`, `createdAt`, `date`, `datetime`, `timestamp`, `time`, `tweet_created_at` |
| `text` | `text`, `full_text`, `fullText`, `rawContent`, `content`, `tweet`, `tweet_text`, `body` |
| `username` | `username`, `userName`, `screen_name`, `handle`, `account`, `author`, `user`, `author.userName`, `user.username`, `user.screen_name` |
| `tweet_id` *(optional)* | `id`, `tweet_id`, `id_str`, `tweetId` |
| `like_count` *(optional)* | `like_count`, `likeCount`, `favorite_count`, `likes` |
| `retweet_count` *(optional)* | `retweet_count`, `retweetCount`, `retweets` |
| `is_retweet` *(optional)* | `is_retweet`, `isRetweet`, `retweeted` |

This covers the default exports of twscrape, Apify's Tweet Scraper, the X API v2, and most Kaggle dumps.
If your export uses different names, add them to `COLUMN_ALIASES` in `src/dogebone/io.py`.

### Collection guidance

- Include **all** posts that mention DOGE / Dogecoin (including bare memes), not just bullish or bearish ones.
  Filtering on sentiment before analysis biases the hit rate. The notebook tags clear-coin vs. ambiguous meme posts itself.
- Keep retweets and quote posts if you can, with the `is_retweet` flag. They're excluded by default but useful for checking robustness.
- Don't hand-edit the text. Emojis, capitalization, and `!!!` are part of the signal.

## Reference data: `data/reference/`

- `key_events.csv`: dated DOGE market events for 2021–2022 (the Robinhood/WSB frenzy, SNL, exchange listings, LUNA/FTX, the Twitter deal),
  used to annotate charts and to sanity-check whether "signals" are just big news days.
